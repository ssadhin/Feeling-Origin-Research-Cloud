11_REAL_CASE_REPLAY_v001 — METHODOLOGY EXTERNAL VALIDATION


STATUS
Completed qualitative replay against failures from the project's actual research history. This is not a blinded quantitative benchmark and cannot by itself establish superiority. Its purpose is to test whether the synthetic-benchmark survivors contain the operators that actually mattered in real project failures.


REPLAY RULE
For each case, ask:
1. What exact failure was later demonstrated?
2. Which operation actually exposed it?
3. Would a proposed methodology have required that operation before the claim/recruitment/promotion point?
4. If not, record a miss rather than granting generic credit for “being rigorous.”


CASE R1 — CRFI V014 BEHAVIORAL NON-UNIQUENESS
Observed failure:
A topology-distinct gated-learning rival matched all frozen behavioral-signature equivalence conditions even without direct S_to_E reciprocal embedding.
Required operations:
strong rival generation; frozen equivalence criteria; confirmatory held-out execution; mechanism-level intervention follow-up.
Method lesson:
Behavioral success and ablation are insufficient if a clean topology-distinct rival can reproduce the signature.
P14/P15 backbone:
GOOD. Pairwise comparison + equivalence + negative-control logic directly matches the failure.
Additional requirement:
preregistered causal discriminator before any renewed uniqueness claim.


CASE R2 — CRFI PRIOR-ART / NOVELTY COLLISION
Observed failure:
After V014, targeted prior-art review found substantial overlap with GNW, IIT, RPT, affective theories, and N*, invalidating earlier novelty/winner language.
Required operations:
systematic prior-art search; strongest-theory steelman; novelty claim ceiling.
Method lesson:
Prior-art audit must occur before promoting a mechanism as novel, not only after a functional failure.
P14/P15 backbone:
MISS as encoded in synthetic policy. Neither contains prior-art search.
Required repair:
novelty/prior-art gate is mandatory when the claim includes novelty, mechanism independence, or “winner” language.


CASE R3 — DEATH-AFFECT 002K IDENTIFIABILITY / PSEUDOREPLICATION
Observed failure:
Naturalistic scenarios structurally aliased the biological target with a death-labeled scenario; engineered matched contrasts reduced coefficient bias but participant-level OLS produced severely inflated false positives because the manipulation had only a few independent vignette families.
Required operations:
pre-human simulation; model recovery/identifiability; unit-of-analysis audit; leave-family-out robustness; calibrated null false-positive checks.
Method lesson:
A numerically estimable coefficient is not causal identification; apparent power is meaningless when Type-I error is broken.
P14/P15 backbone:
MISS if used literally. General compare/equivalence is insufficient.
Required repair:
model-recovery/identifiability gate is mandatory before human recruitment or mechanism claims based on model selection.


CASE R4 — ESTIMATOR SUITE v1 SOFTWARE CONTRACT / REDUNDANCY
Observed failure:
A process-ensemble software-contract issue required correction before freezing; complete-class tests also showed strong R/O redundancy, warning against treating named primitives as independent.
Required operations:
unit/invariant/metamorphic software tests; complete-class/minimal implementation audit; redundancy/equivalence analysis.
Method lesson:
Scientific inference is blocked when executable definitions are not validated; formal named variables must earn distinctness.
P14:
PARTIAL/MISS — lacks MIST and software validity.
P15:
PARTIAL — MIST helps redundancy but still lacks mandatory software validity.
Required repair:
software-validity gate for any code-dependent claim; MIST only when the claim depends on formal criterion specificity/minimal realization.


CASE R5 — METHODOLOGY BENCHMARK HASH-ORDER NONDETERMINISM
Observed failure:
Benchmark trajectories depended on Python set iteration / PYTHONHASHSEED.
Required operations:
cross-process reproducibility test; deterministic ordering; immutable rerun.
Method lesson:
same-process repetition is too weak for software validity.
P14/P15:
MISS as encoded.
Required repair:
software validity must include nuisance-environment perturbation, not only ordinary unit tests.


CASE R6 — RFS / STIMULUS BANK VALIDITY
Observed failure:
Candidate prose stimuli leaked structural cue words, explicitness, length/event-count differences, and bottleneck/common-cause ambiguity. Main human experiment was blocked pending measurement/stimulus validation.
Required operations:
measurement audit; independent stimulus validation; nuisance matching; cheap pilot kill gate before main experiment.
Method lesson:
construct and stimulus validity must be demonstrated before expensive causal testing.
P14/P15:
MISS as encoded.
Required repair:
measurement/stimulus-validity gate is mandatory when experimental constructs are represented through items, vignettes, questionnaires, or proxy measures.


SYNTHETIC + REAL-CASE SYNTHESIS
1. Recursive rival search is strongly supported as the backbone.
2. Equivalence/underdetermination and ancestor challenge are high-value cheap gates and should occur before expensive verification.
3. Fixed maximal verification is inefficient and underperformed.
4. MIST is useful but not universal; it is justified when formal criterion specificity/minimal realization/redundancy is at issue.
5. Software validity is not optional for code-dependent science.
6. Prior-art/novelty audit is not optional for novelty claims.
7. Model recovery/identifiability is not optional when inference depends on distinguishing models/constructs or when a human study could be underidentified.
8. Measurement/stimulus validity is not optional before experiments using proxies/items/vignettes.
9. Causal intervention, multiverse, sensitivity, replication, and OOD should be triggered by the live claim/failure class rather than run mechanically in every project.
10. The best-supported methodology therefore has a recursive core plus claim-type gates and state-dependent escalation.


REAL-CASE VERDICT
P14 and P15 are strong synthetic benchmark backbones but are incomplete as literal research methodologies for this project.
The best-supported operating policy is a new synthesis:
Adaptive Epistemic Search v2 — Gated Recursive Tournament.
It keeps the P14 recursive/equivalence/ancestor spine, treats MIST as conditional, and adds mandatory front-door gates for software validity, prior art, identifiability, and measurement validity when their triggering claim/task types are present.


CLAIM CEILING
This is the best-supported methodology for the current project's research class based on:
- frozen synthetic locked test;
- held-out OOD composite test;
- replay against real project failures;
- convergence with external benchmarking principles.
It is not established as the universally best scientific method.
